# 🎨 Стайлгайд и лучшие практики (Styleguide)

## 1. Язык и коммуникация

- **Язык интерфейса:** только русский. Все тексты, кнопки, сообщения об ошибках должны быть на русском языке.
- **Язык общения:** нейросеть/агент обязана отвечать пользователю и вести документацию на русском языке.
- **Код:** имена переменных и функций - на английском (camelCase, PascalCase).

## 2. Правила документации

- **Регистр заголовков (Sentence case):** пишем заголовки как обычные предложения. Первая буква заглавная, остальные строчные. Английские термины в скобках можно писать в Title Case.
  - ❌ Неправильно: Настройка Скалы
  - ✅ Правильно: Настройка скалы (Setup Phase)
- **Двоеточия и списки:**
  - Если текст идет сразу после двоеточия в той же строке - пишем с **маленькой буквы**.
    - _Пример:_ Цель: победа над дисфункцией.
  - Если после двоеточия идет перенос строки (начало списка) - пишем с **Большой буквы**.
    - _Пример:_
      Цели проекта:
      1. Избавить от мук выбора.
      2. Дать дофамин.
- **Пунктуация:** используем только дефис `-` (минус). Никаких длинных тире `—` или средних тире `–`.

## 3. Основные принципы

- **Clean Code:** код должен быть самодокументируемым. Названия переменных должны четко отражать суть.
- **Никаких комментариев:** код должен быть настолько понятным, что комментарии не требуются. Если хочется написать комментарий - перепишите код.
- **Атомарность:** компоненты должны быть маленькими. Если файл больше 150 строк - рефакторим.
- **UX/UI прежде всего:** удобство пользователя - приоритет.

## 4. Технологический стек

- **Фреймворк:** Vue 3 (Composition API с `<script setup>`).
- **Стили:** **Tailwind CSS** обязателен.
  - ❌ Никаких инлайн-стилей (`style="margin: 10px"`).
  - ✅ Используйте утилитарные классы (`m-4`, `flex`, `text-red-500`).
- **Состояние:** Vue `reactive` или `ref` для локального. Pinia (или composables) для глобального.

## 5. Vue 3: критичные правила

- **`defineProps` и `defineEmits` - макросы компилятора.** Они работают ТОЛЬКО на верхнем уровне `<script setup>`. Вызов внутри функций приводит к ошибке компиляции SFC.
  - ❌ Неправильно:
    ```ts
    function toggle() {
      emit('update', !defineProps<Props>().value); // Ошибка компиляции!
    }
    ```
  - ✅ Правильно:
    ```ts
    const props = defineProps<Props>();
    function toggle() {
      emit('update', !props.value);
    }
    ```

## 6. Критерии приемки

- Интерфейс минималистичен? Нет ли визуального шума?
- Все ли тексты на русском? Соблюдены ли правила регистра?
- Нет ли "магических чисел"? (выносить в константы).

## 7. Тестирование

- **Покрываем бизнес-логику, не фреймворк.** Не тестируем геттеры, сеттеры, computed-обёртки. Тестируем функции с условиями и побочными эффектами.
- **Приоритет:** функции, влияющие на поведение приложения (валидация, расчёты, переключение состояний).
- **Названия тестов:** на русском, описывают что проверяется.
  ```ts
  it('должен блокировать сайд-квесты в хардмоде', () => { ... });
  ```
- **Структура теста:** Arrange → Act → Assert. Одна проверка на тест.
- **Не мокаем без необходимости.** localStorage - исключение (мокаем всегда).
